# SNES 실기 결과 및 릴리즈 반영 — 2026-10-02

최신 결론: **마리오 월드의 현재 slot 0 저장 장면에서 340MHz + 벌크 대기 루프가
일반 adaptive 렌더로 60.132 drawn FPS를 달성했다.** 측정 900프레임 전부를 그렸고
해당 구간의 음원 dry-sample counter 증가는 0이었다. 젤다는 같은 클록에서 전 프레임
렌더 57.245 FPS이며, 이번 벌크 변경의 효과는 거의 없었다. 전체 게임·모든 장면의
지속 60 FPS를 검증한 결과는 아니다.

## 채택과 제외

- 릴리즈 후보에는 `external/sm`의 `e33537c06618e88786f518221787a1e033ba303b`
  완전한 대기 반복 구간 계산과 `SNES_BAKE_BULK=1`을 반영한다.
- 기존 오디오 모드·속도·피치 정책과 CPU 기본 선택은 바꾸지 않는다.
  **이번 60 FPS 확인 조건은 기기 CPU 메뉴 level 2, 340MHz**다.
  사용자가 CPU를 선택하지 않은 설정에서는 SNES가 312MHz로 동작한다.
- 파형 탐색 SIMD/스냅샷 후보는 릴리즈 동작에서 제외한다.
  실기 추가 이득은 0.124%에 그쳤다. `SNES_STRETCH_PACKED_PICK=0`으로
  릴리즈의 활성 음원 구현은 변경하지 않는다.
  실험 소스/하네스는 perf/snes-60fps-span와 증거 snapshot에 남긴다.
- `SNES_DEVICE_BENCH=0`으로 완료 계측 훅은 릴리즈에서 제거한다. profiler와
  릴리즈 바이너리에 넣지 않는다. 최신 32X를 과거 SNES 기준으로 되돌리지 않는다.

## 실기 A → B → A

모든 숫자는 drawn FPS다. 음원 탐색 후보 행만 A/B 모두 bulk=1이고 B만 packed picker=1이다.
나머지는 A bulk=0, B bulk=1. 각 행은 고정 triplet 1회다.

| 마리오 월드, 기본 렌더 1 | 312 | 40.603 | 51.190 | 40.245 | -0.880% | 드리프트 무효 |
| 마리오 월드, 기본 렌더 2 | 312 | 41.258 | 52.369 | 39.603 | -4.013% | 드리프트 무효 |
| 마리오 월드, 기본 렌더 3 | 312 | 38.951 | 50.317 | 36.385 | -6.586% | 드리프트 무효 |
| 드래곤즈 매직, 기본 렌더 | 312 | 60.148 | 60.148 | 60.148 | +0.000% | 구간 관측 |

312MHz 마리오 월드의 adaptive 비교는 3개 triplet 모두 기준판 드리프트 한계
0.5%를 넘겼다. 평균 증가 수치를 채택 근거로 쓰지 않는다. 동일한 900장 전부를
그린 비교는 54.322 → 58.586 FPS, +7.851%, A 드리프트 +0.060%였다.

340MHz의 전 프레임 비교는 57.915 → 60.189 FPS, +3.926%, A 드리프트 0%다.
일반 렌더 B도 **900/900장, 60.132 FPS, dry-sample 증가 0**을 확인했다.
일반 렌더 A 드리프트 -0.819% 때문에 그 triplet의 +22.8%라는 상대 개선율은
무효로 보존한다. B의 절대 프레임 수·경과 시간·guest 진행 관측과 비교 개선율을
구분한다. 드래곤즈 매직은 기존 A도 같은 초기 구간에서 이미 60.148 FPS였다.

## 입력과 정확성

실기 ROM과 기존 slot 0 저장을 직접 백업/해시하고, 저장 payload CRC와 로드 직후
직렬화 CRC가 일치하는지를 각 arm에서 확인했다. 입력은 없음, 로드 후 120프레임
워밍업, 다음 900프레임(120..1019)을 측정했다. guest frame counter는 저장 구조에
없으므로 이 번호를 과거 저장 시점의 frame 번호라고 해석하지 않는다.

- 젤다 ROM SHA-256 `66871d66be19ad2c34c927d6b14cd8eb6fc3181965b6e517cb361f7316009cfb`,
  payload CRC32 `974483862`.
- 마리오 월드 ROM SHA-256 `0838e531fe22c077528febe14cb3ff7c492f1f5fa8de354192bdff7137c27f5b`,
  payload CRC32 `636344236`.
- 드래곤즈 매직 ROM SHA-256 `f1331e982e86362fe5c5b41279d3d676d54626db0b31f51dcb91a566c8808648`,
  payload CRC32 `3888663078`.

모든 완료 triplet에서 guest 마지막 상태 CRC, 마지막 LCD 화면, 마지막 raw DSP PCM
블록이 같았다. 이것은 **실기 전체 재생 음원 스트림의 동일성 근거는 아니다**.
기존 벌크 하네스는 109,886 span 차등검증 및 ASan/UBSan, 9게임·12조건·30,000
프레임의 상태/화면/음원 비교를 통과했다. [기존 하네스 기록](SNES_HARNESS_READY_2026-10-01.md).

음원 후보는 605개의 wrap/극값/무음/노이즈 탐색 창과 M7의 실제 SMLALD 경로를
통과했다. QEMU 탐색 명령 타이머는 56,914 → 13,538(76.2% 감소)였지만 이는
하드웨어 cycle/FPS가 아니다. 9게임 × 7일정 × 2모드 = 126조건에서 최종 PCM과
진단 값이 같았다. overflow burst와 실시간 모드 전환도 포함했다. 이 host 비교는
ISR이 탐색 중 rd를 바꾸는 경우를 포함하지 않으며, 후보는 이를 일관된 cursor
스냅샷으로 바꾸므로 해당 동시성에서 byte 동일성을 주장하지 않는다.

## 소리와 측정 한계

사용자는 전 프레임 진단 중 소리가 맥빠진 듯하다고 했고, 이후 세션 중에는
“아까보다 좋아졌네”라고 했다. 정확히 어느 arm의 어느 구간을 들었는지는 따로
기록하지 않아 블라인드 A/B 청감 판정으로 쓰지 않는다. Gap-free는 부족한 생산량을
재생 비율로 따라가므로 느린 구간의 낮아진 음 높이를 비용 없는 성공으로 보지 않는다.
이번 릴리즈는 그 정책을 수정하지 않는다.

`audio-hardware.json`의 step/base/fill은 완료 state CRC 작업 뒤의 값이다.
그 작업 동안 추가 샘플 생산이 멈추므로 **정상 측정 구간의 재생 비율로 쓰면 안 된다**.
record의 dry-sample counter는 측정 종료 시점에 먼저 캡처한다. 전 프레임 진단의
시작 debugger 정지 동안 ring이 소모되는 영향도 있어 dry-sample 전체를 steady-state
음질로 단정하지 않는다. 일반 모드 340MHz B의 측정 구간 증가 0은 별도로 기록한다.

## 장치·브랜치 보존과 산출물

글로벌 `/tmp/gnw-swd.lock`을 획득한 유한 실행기가 flash/readback/start를 수행하고,
펌웨어 완료 breakpoint에서 한 번 수집했다. frame/SWD 진행 폴링·부팅 자동 retry는
없다. 처음 smoke에서 HAL tick과 외부 monotonic 시간을 비교했고 전 프레임 진단은
각 arm에서도 검증했다. arm별 intflash와 SD core hash를 서로 일치시켰다.

중간에 다른 작업이 기기 firmware/core를 교체한 것이 입장 검사에서 발견되어,
첫 음원 실험 시도는 **flash 전에 중단**했다. 실패 기록을 남기고 새 상태를 보존한
후 새 case로 진행했다. 모든 완료 case는 실행 직전의 firmware/core/CONFIG/selector를
정확히 복원하고, slot 0 save와 off.sav 불변성을 readback으로 확인했다. 마지막 복구는
새 32X 펌웨어 상태를 보존했다. 메인 `testbed`를 switch/reset하지 않았다.

- [ROM 없는 실기 증거 manifest](../tools/snes_device_bench/results/20261002/manifest.json):
  완료 case 10개, 무효 비교·입장 실패, raw record, 화면 gzip, 음원 endpoint,
  원본 로그, 빌드/입력/소스 hash와 초기·최종 도구 snapshot.
- 원본 입력·전체 ELF·복구 덤프는 로컬 `build/`에 유지한다. Git에 ROM이나 전체 save를 넣지 않는다.
- 빌더 `sylverb/retro-go-sd-builder:v1.5`, image SHA
  `948725b822603810687c2b0331d0105c30167f4cf8157b210fd452f20db94691`, GCC 15.2.1.
  canonical 기능/언어/boot OC/bank 2 옵션. profiler OFF.
- `build/snes-playable-bulk-20261002/arm/`에는 계측 완료 정지를 제거한 별도 intflash+SNES
  실험 쌍을 만들었다. 링크·alias/logo/init-array/XIP/profile-off 검사와 계측 symbol 부재를
  확인했다. 이 hook-free 재링크 자체는 실기에 다시 올리지 않았고 최신 통합 릴리즈는 아니다.
- 최신 32X와 통합한 최종 release package는 별도 canonical release build 및 CI gate를 따른다.

젤다의 다음 후보는 현재 무거운 CPU/PPU 구간이어야 한다. 이번 대기 구간 계산만으로
젤다 60 FPS에 도달했다고 보고하지 않는다. 사용자 요청에 따라 추가 최적화는 여기서 종료한다.
