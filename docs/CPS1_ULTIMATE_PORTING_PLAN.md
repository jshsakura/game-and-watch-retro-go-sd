# ⚔️ 천지를 먹다 2 (CPS-1) 740KB RAM 돌파를 위한 초절감 극단적 마스터플랜

> **목표**: 740KB 가용 램을 가진 Game & Watch에서 CPS-1 전성기 명작 **'천지를 먹다 2 (Warriors of Fate)'**를 프레임스킵 최소화(60fps 타겟) 및 사운드 끊김 없이 실기 구동한다.
> 
> **핵심 사상**: 에뮬레이트하려는 하드웨어 스펙이 우리의 물리 램보다 크다면, 하드웨어를 소프트웨어로 흉내 내는 일반적인 방식을 버려야 합니다. 임베디드 칩(STM32H7)의 하드웨어 특성(ITCM/DTCM, DMA2D, OSPI XIP)을 활용해 **에뮬레이터의 오버헤드를 무수히 쪼개서 분산시키는 초절감 기법**을 총동원합니다.

---

## 1. 68000 CPU: Static Recompilation & Register Mapping
런타임에 68000의 명령어를 바이트 단위로 해석(Fetch/Decode)하는 것은 M7 성능에 큰 낭비입니다. 68000 코드를 네이티브 Cortex-M7 기계어로 사전 변환합니다.

### 💡 기법 1: 68000 to C Static Recompiler (정적 재컴파일러)
* **개념**: 롬셋의 68000 프로그램 바이너리(약 1.5MB)를 빌드 타임(호스트 PC)에 정적 분석하여, 각각의 68000 명령어를 C언어 코드로 1:1 번역한 C 파일로 소스 코드를 생성합니다. (이미 본 프로젝트의 SNES 젤다3, 메트로이드 포트에서 검증된 방식).
* **예시**:
  ```c
  // 68000: ADD.W D0, D1
  d1 = (d1 & 0xFFFF0000) | (((d1 & 0xFFFF) + (d0 & 0xFFFF)) & 0xFFFF);
  ```
* **효과**: 런타임 인터프리터 루프와 명령어 해석 비용이 **90% 이상 제거**됩니다. 생성된 C 코드는 GCC가 컴파일하여 OSPI Flash 영역에 네이티브 M7 기계어로 안착하며, 런타임 RAM 소모량은 `0` 바이트가 됩니다.

### 💡 기법 2: ARM 물리 레지스터 1:1 매핑 (ITCM 적재)
* **개념**: 가상의 68000 레지스터 구조체(`D0~D7`, `A0~A7`, `PC`)를 램에 두지 않고, GCC의 글로벌 레지스터 지정 플래그 또는 인라인 어셈블리를 통해 ARM Cortex-M7의 물리 레지스터(`R4`~`R11`)에 직접 강제 매핑합니다.
* **효과**: 가상 레지스터를 변경할 때 발생하는 메모리 읽기/쓰기 사이클이 원천 차단되고 순수 CPU 레지스터 연산으로만 동작합니다.

## 2. CHR ROM (그래픽): Palettized LRU 캐시 & DMA2D 블릿
수 메가바이트의 그래픽 롬셋 데이터를 740KB 램 내에서 고속 드로잉하기 위한 극단적인 리소스 절약 기법입니다.

### 💡 기법 3: Palettized 4bpp/8bpp 캐시 (캐시 효율 200% 상승)
* **개념**: 캐시 메모리(256KB)에 타일을 미리 RGB565(픽셀당 16비트/2바이트)로 디코딩해서 올려두면 램이 금방 바닥납니다. 대신, 그래픽 롬에 압축된 원본 **4bpp(또는 8bpp 인덱스) 포맷 그대로 캐싱**합니다.
* **효과**: 동일한 256KB RAM 용량에 **2배 더 많은 스프라이트 타일**을 캐싱할 수 있습니다. 512KB RAM 캐시를 쓰는 것과 동일한 효율을 냅니다.

### 💡 기법 4: 하드웨어 DMA2D (Chrom-ART) 가속 Blit
* **개념**: 화면을 그리는 최종 렌더링 시점에만 4bpp 인덱스 이미지와 팔레트 테이블을 조합하여 화면 버퍼로 전송해야 합니다. 이 픽셀 변환 및 알파 채널 투명 처리를 CPU가 아닌 STM32H7의 **하드웨어 DMA2D 가속기**를 사용하여 즉석에서 수행합니다.
* **효과**: 화면 픽셀 복사 및 투명 처리에 소모되는 CPU 점유율이 0%에 수렴하게 되어, 그래픽 오버헤드가 극적으로 줄어듭니다.

### 💡 기법 5: OAM 프리스캔 & 공간 필터링 (Spatial Pre-filtering)
* **개념**: 화면 바깥 영역의 스프라이트는 플래시에서 읽거나 캐싱할 필요가 없습니다. 프레임 렌더링 전 CPS-1의 Object RAM(OAM)을 먼저 훑어서 화면 해상도($320 \times 240$) 내에 정확히 위치하는 활성 스프라이트 ID만 리스트업하고, 해당 타일들만 캐시에 로딩합니다.
* **효과**: 플래시 메모리 읽기 대역폭 소모를 최소화합니다.

## 3. 오디오: Z80 + YM2151 APU HLE (High-Level Emulation)
오디오 연산은 에뮬레이션에서 CPU 성능을 가장 많이 갉아먹는 주범 중 하나입니다.

### 💡 기법 6: QSound / CPS-1 사운드 드라이버 HLE
* **개념**: Z80 CPU 에뮬레이터와 복잡한 YM2151 FM 합성 칩을 통째로 돌리는 하위 레벨 에뮬레이션을 과감히 포기합니다. 천지를 먹다 2 사운드 드라이버의 시퀀서 데이터 형식과 사운드 레지스터 프로토콜을 분석하여, **M7 네이티브 C 코드로 음악 시퀀스를 직접 해석**해 내는 HLE 플레이어를 얹습니다.
* **오디오 믹싱**: 효과음(OKIM6295 ADPCM 샘플)은 SD 카드/Flash에서 직접 실시간 스트리밍하되, Cortex-M7의 **ARM CMSIS-DSP 라이브러리**의 고속 믹싱 기능을 활용하여 초저비용으로 오디오 채널을 병합합니다.
* **효과**: 오디오 에뮬레이션에 소모되던 성능 예산을 30% 이상 아껴 CPU 처리량으로 돌릴 수 있습니다.

## 4. STM32H7 하드웨어 메모리 극단적 분할 (Linker Map)

740KB 가용 RAM의 물리 주소 공간을 STM32H7의 독립된 하드웨어 버스/SRAM 영역에 강제 배치하여 병목을 원천 봉쇄합니다.

```
+------------------------------------------------------------------------+
| 64KB DTCM (Tightly-Coupled Data RAM - 속도 최고)                        |
| -> 68000 핵심 WRAM (64KB) 및 가상 CPU 상태 변수 배치                     |
+------------------------------------------------------------------------+
| 64KB ITCM (Tightly-Coupled Instruction RAM - 속도 최고)                  |
| -> DMA2D 비디오 블리터 핵심 루프 및 인터럽트 서비스 루틴(ISR) 적재         |
+------------------------------------------------------------------------+
| 512KB D1 AXI SRAM (메인 램 영역)                                       |
| -> CPS-1 가상 VRAM (192KB) 및 OAM/Palette (12KB) 적재                    |
| -> 256KB Dynamic Palettized LRU CHR Cache 배치                         |
+------------------------------------------------------------------------+
| 64KB D2 SRAM3 (독립 버스 영역)                                          |
| -> 오디오 스트리밍 더블 버퍼 및 시스템 힙/스택 영역 배정                 |
+------------------------------------------------------------------------+
```

## 🚀 단계별 실행 마스터 로드맵

1. **[1단계] PC 호스트 빌드 환경 구축 (linux/ 포팅)**:
   * PC 환경에서 CPS-1 standalone 경량 코어를 컴파일하고 `Tenchi wo Kurau I (1.5MB)`의 정적 재컴파일러(Static Recompiler)를 돌려 부팅 및 구동 상태를 먼저 검증합니다.
2. **[2단계] STM32 링커 스크립트 분할 및 DTCM 배치**:
   * [STM32H7B0VBTx_SDCARD.ld](file:///home/ubuntu/app/jupyterLab/notebooks/game-and-watch-retro-go-sd/STM32H7B0VBTx_SDCARD.ld) 상에 `.overlay_cps1` 전용 버퍼를 설계하고, WRAM을 DTCM에, 캐시 버퍼를 AXI SRAM에 정적 바인딩합니다.
3. **[3단계] LRU CHR 캐시 및 DMA2D 블리터 구현**:
   * OAM 프리스캔 및 4bpp 캐싱 모듈을 구현하고, DMA2D 가속을 통한 화면 픽셀 매핑 처리를 얹습니다.
4. **[4단계] 실기 프로파일링 및 튜닝**:
   * 실기 플래싱 후 DWT 프로파일링을 활성화하여 병목 구간을 탐색하고, 천지를 먹다 2(6MB)로 대상을 확장하여 튜닝을 마무리합니다.
