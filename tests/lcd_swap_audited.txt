# Every file that CALLS lcd_swap() or lcd_swap_stale(), with the counts and the
# verdict from reading its loop. tests/test_lcd_swap_audited.sh fails when this
# list and the tree disagree.
#
# WHY THIS EXISTS. g_common_drawn_frames is incremented in lcd_swap(), so a core
# that skips its render and flips anyway reports every frame as drawn. Three did
# (gwenesis, msx, celeste) and would have read a flat 100%; they call
# lcd_swap_stale() now -- the identical flip, not counted. The previous counter
# had the mirror-image defect, counting the guard's DECISION for cores that
# discard it, and Virtual Boy went into the ledger at 9 drawn fps while it was
# presenting 36. Both mistakes look exactly like a measurement.
#
# So a new core, or a changed count in an old one, has to be READ before this
# file is edited. That is the whole mechanism: the check is arithmetic, and the
# thinking is here.
#
# HOW TO UPDATE. Do NOT classify from the lines around the lcd_swap(). Find the
# `= common_emu_frame_loop()` assignment first, then find every use of what it
# was assigned to. Three cores were filed wrong here because the verdict was
# read off an 8-line window around the swap and their `if (drawFrame) {` opened
# fourteen lines further up: zelda3, smw and tamapoke were all called
# "always-draws" when all three obey the guard. The counts were right, so the
# gate stayed green and the wrong verdicts sat in the column that decides
# whether a reading is a defect.
#
# Then answer one question -- when this core skips a frame, does new content
# still reach the back buffer?
#   yes, always  -> it ignores the guard and draws everything: lcd_swap(), and
#                   drawn == emu is the CORRECT reading (vb, videopac; c64_dev,
#                   lynx, a2600 and zxs discard the return value entirely)
#   no           -> lcd_swap_stale() on the skip path (celeste)
#   sometimes    -> the condition is the core's, not the guard's (msx: in screen
#                   modes 10/11/12 the VDP writes the LCD buffer itself)
# Then add the line here with which of those it is.
#
# ONE PIECE OF VOCABULARY, because two independent reviewers got it backwards on
# the same day: **lcd_get_active_buffer() returns the buffer the CPU DRAWS INTO,
# not the one on screen.** gw_lcd.c:298 hands back `active_framebuffer ? fb2 :
# fb1`, while HAL_LTDC_ReloadEventCallback (gw_lcd.c:180) points the LTDC at the
# other one. Both reviewers concluded gwenesis:894 presents a stale buffer; it
# does not -- it presents the frame rendered before the overflow, which had
# never been shown.
#
# FIELDS: <path> swap=<n> stale=<n> <verdict> # reason
#   ui           not an emulation loop; launcher/menu/player paint. NOT a
#                promise that it cannot fire during a game -- two of them do
#                (see rg_alarm.c and odroid_overlay.c below), and the reason the
#                counter survives that is that drawn_ab.sh flags `drawn > emu`,
#                which is exactly the shape a UI flip makes when emulation has
#                stopped.
#   gated        the swap sits inside the core's own `if (drawFrame)`, so a
#                skipped frame never flips. Nothing to do.
#   always-draws the core renders unconditionally and flips unconditionally.
#                drawn == emu is the truth for it, not a bug.
#   split        the core flips on every frame but only sometimes with new
#                content -- the three that need lcd_swap_stale().
#   dead         not built by any configuration in this tree.
#   defines      where the functions are defined or declared, not called.
#   prose        mentions the name in a comment or a string and calls nothing.
#                Listed anyway, with swap=0 stale=0, so the census fails CLOSED:
#                a parser bug that zeroes a real file's counts then mismatches
#                its audit instead of dropping the file from the scan. One did.
#
# WHAT A COUNT CENSUS CANNOT SEE. Counts are preserved by an EXCHANGE. This
# regression passes:
#
#   - if (drawFrame) { blit(); lcd_swap(); } else { lcd_swap_stale(); }
#   + if (!drawFrame) { lcd_swap(); }       else { blit(); lcd_swap_stale(); }
#
# swap=1 stale=1 before and after, and every skipped frame is now reported as
# drawn -- the exact defect this file exists to prevent. Nothing here will say
# so. Reviewing a diff that touches both calls in one file is the only guard.
#
# NOT COVERED, on purpose: Core/Src/retro-go/gw_firmware_abi.c exports lcd_swap
# as a function pointer (gw_firmware_abi.h:183) and there is no lcd_swap_stale
# in the ABI. An external core reached through that pointer cannot be seen by a
# grep of this tree and cannot opt out of being counted. Nothing in this repo's
# firmware uses it that way yet; when one does, that is an ABI decision, not a
# line in this file.

# gwenesis, in detail, because it is the one that looks like the others and is
# not. main_gwenesis.c:777 reads
#
#     // bool drawFrame =
#     common_emu_frame_loop();
#
# The assignment is COMMENTED OUT. The guard's answer is discarded. drawFrame is
# a file-scope global (:308, initialised to 1) and the only code that ever
# writes it lives inside `if (gwenesis_vsync_mode)` (:891, :895). Audio-sync is
# the default (:63), and in that mode nothing assigns drawFrame for the life of
# the process -- so the render at :851 always runs, the flip at :908 (the `else`
# of gwenesis_vsync_mode) always takes lcd_swap(), and MD genuinely draws every
# frame it emulates. drawn == emu is the TRUTH here, and lcd_swap_stale() (:910)
# is unreachable in the default mode.
#
# The three flips in that file are :894 (vsync branch, counted), :908 (audio-sync,
# counted) and :910 (audio-sync, stale). Branch names are given alongside the
# numbers on purpose: the commit that first wrote these references quoted :903,
# and was already wrong when it landed, because the same commit inserted the
# stale branch that pushed the line down.
#
# It is still not dead code, which is why the call stays. Toggle vsync on, hit
# an overflow (drawFrame = 0 at :891), toggle back to audio-sync with the option
# at :438, and drawFrame is stuck at 0: the render stops, the flips continue,
# and the panel freezes. That is a pre-existing bug, not one this counter
# introduced -- but under the old code that frozen screen also reported
# drawn == emu, and now it reports the truth.
#
# Consequence for anyone measuring: MD CANNOT judge this counter. Both a fixed
# and an unfixed build read ratio 1.0000, at any speedup, because the guard
# cannot make this core skip. Worse, common_emu_state.skipped_frames keeps
# counting -- the `+=` at common.c:215 happens inside common_emu_frame_loop(),
# before gwenesis zeroes skip_frames -- so it reports what the integrator WANTED
# while nothing was ever skipped. Use celeste (:677 assigns, :696 gates, no mode
# nuance) or msx (:2143, :2172, avoiding screen modes 10/11/12).
# ---------------------------------------------------------------------------
